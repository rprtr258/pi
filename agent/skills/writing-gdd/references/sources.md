# Sources — GDD research (2026)

| # | Source | Key contribution |
|---|--------|------------------|
| 1 | [Дизайн-документ игры (Habr, RU)](https://habr.com/ru/articles/469971/) | Classic 10-page template (from Scott Rogers, *Level Up!*): general info, story summary, character, gameplay, world, experience flow, mechanics, enemies/bosses, cutscenes, bonus content. Includes a War Robots game-mode example. |
| 2 | [Как написать дизайн-документ для игры (Skillbox, RU)](https://skillbox.ru/media/gamedev/kak_napisat_dizayn_dokument_dlya_igry/) | GDD is a working document, not literature. Precision examples ("hit opponents" → exact control scheme + numbers). Story = setting + synopsis only; full script goes elsewhere. Visuals = direction + references, not pixel specs. Tools: Google Docs, draw.io, spreadsheets. |
| 3 | [Write docs for the humans who read them (johnjago.com)](https://johnjago.com/great-docs/) | General doc craft (esbuild, Redis examples): know the audience, table of contents, explain the *why* behind design decisions, use visuals and examples. |
| 4 | [How to write a game design document (GitBook)](https://www.gitbook.com/blog/how-to-write-a-game-design-document) | Modern GDD anatomy: vision paragraph, design pillars, **non-goals**, core loop, systems, content, UX/UI, production. Living document, updated through development. Famous GDDs: DOOM bible, GTA (Race'n'Chase), Deus Ex annotated, Grim Fandango. |
| 5 | [One-page game design document (Unity blog)](https://unity.com/blog/one-page-game-design-document) | One-pager fields: one-sentence concept, core loop (3–4 verbs), win/lose, controls, MoSCoW priorities (must/should/could/**won't**), look & sound, inspiration, audience, done-means checklist. Scope-creep control; evolve, don't perfect. |
| 6 | [How to make a professional GDD (Strudo)](https://strudoapp.com/articles/how-to-make-a-professional-game-design-document-gdd) | Production view: separate pitch / concept doc / GDD / bible. GDD is a **technical document organized by systems and subsystems**, each with its own skeleton (objectives, overview, screen flow, behavior/mechanics, balance, art, audio, analytics, tools/QA, references, version history), priority labels (Essential/Optional/Future), numbers and state machines instead of adjectives, versioning + changelog. Super Mario Bros worked example. |
